# 接口依赖、真实入口和返修

## 示例

虚构搜索应用：取消后结果清空，迟到响应不能覆盖新查询，正常搜索仍返回。Lead 先核实现象、期望、事实、假设、真实入口和现有测试；已有确认计划不重做调查。A 提供 request(query) → {promise,cancel}，B 消费并保护控制器编号。取消后底层仍可能响应的异步语义在交接中写明。

A 先交接口，B 先做不受阻的编号保护；真实入口接通属于 B 原任务。各有唯一文件/状态所有权，可靠工作区与基准，保留用户改动；mock 只证明局部，不能替代联合行为。角色沿用已有授权，新增/更换才补决定。

```ts
const id = ++this.requestId;
const request = this.service.request(query);
this.activeRequest = request;
const results = await request.promise;
if (id !== this.requestId) return;
this.results = results;
```

取消还要使编号失效、调用当前 request.cancel 并清空结果；正常/错误回调按实际项目契约处理。本片段不是完整实现或所有项目模板。

Deep Reviewer 发现 startSearch 仍走旧服务：给文件位置、触发路径和影响，结论 FIX，不能因为有新保护方法就 PASS。若代表样例只写第一次取消，第二次取消同样失败仍是原需求缺陷。缺运行环境导致测试没进入路径则 BLOCKED，明确命令、错误和受影响用例，不把“不抛异常”当通过。报告与问题列表矛盾时 Lead 澄清，有阻断缺陷按 FIX。

FIX 退原 B，在原 worktree、新基准、审查证据和已有效调查上修真实入口；定向验证取消、迟到响应和正常结果。已有复审授权自动接续，否则只补角色决定。Pi 复审仅看此缺陷、变更及直接影响，保留 A 的有效结论；新验收缺陷继续报告。连续返修最多两轮，指定验证首轮失败只一次定向修复，诊断两轮无新产品证据收敛，后台复盘按独立配置计额。

正常完成的 Codeg 包接新委派会话；中断先确认原任务停止，保留修改、检查点、有效证据和剩余检查。启动认证失败先看真实错误，不反复重启或猜计费；余额中断不能算交付。更换负责人明确交接，不让接手者重做整轮调查。

必要审查全部 PASS 后按依赖集成并做组合回归，全套失败和定向通过分别说清。人工步骤：开始 A，立即开始 B，取消 B，等待响应，确认旧结果不回填，再开始正常查询。未收到实际用户反馈仍人工待验。

Worker 随交付报告旧经验依赖同步恢复、现版本已异步的候选，Reviewer 核证据与反例，Lead 采集带旧知识 ID 的反例，后台修订条件并保留旧证据/原因。下次相关任务检查条件再用新条目。用户中断不触发知识补偿或恢复业务。提交和发布分开授权，示例通过结果不当成当前仓库证据。
