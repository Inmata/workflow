# 例行操作与小任务

## 示例

以下是行为案例；真实本地 Git 实测见 test/integration.test.mjs 的运行记录，真实 ACP/人工结果单独记录。

| 请求 | 最少角色与行为 | 完成证据 |
| --- | --- | --- |
| 查看状态 | Lead，operation-only，零 Worker/Reviewer | 真实 git status，不改知识 |
| 推送指定提交 | 核对目标远端/分支/提交后按授权 push，零辅助角色 | 远端对应提交；不 add/commit 未提交内容 |
| 无冲突快进拉取 | 核对工作区、目标及可快进条件，保留用户改动 | 实际本地分支和目标相符；不因拉取别人代码全仓审查 |
| 分叉/冲突 | 只暂停策略决策和重估受影响范围 | 不猜合并方式、不顺手修其他模块 |
| 单点文本修正 | Lead 可直接做，读原文，检查具体差异 | 无需为低影响文本建立测试框架 |
| 权限校验一行变化 | 关键行为，安排必要独立审查 | 一行代码仍有真实触发/权限边界证据 |

项目只有 README/零散计划也能接入，不强制建空资料。spec 叫 design-spec.md 就保留名称；需求 500 条、实现 100 条分别写明，不能降低需求使报告变绿。没有新材料直接交付，不要求每轮经验处置。

单点修改扩大为真实代码修复时重新评估相关验证和角色，不因原任务小而免审关键行为。已指定角色与并发上限沿用，缺失角色才明确。工具提问/文本反问先 waiting-user；中断只留状态，下次不能自动继续业务。四种停止限制按各自作用域执行。
