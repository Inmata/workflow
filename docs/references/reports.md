# 阶段反馈

## 报告

每包、审查、返修和阶段结果及时报告；临时进度只说明新结果、阻塞或实际调整，无变化不重复。还有角色运行时继续协调；全终态后汇总推进或交用户。默认主对话报告，不为日常反馈创建额外文件。

先讲用户能理解的行为变化，再说原因、必要证据、目前成果和未完成。标清工作包、阶段、负责人、版本和真实命令，说明依赖满足什么才能继续，以及最小下一步、负责人和是否已启动。术语用于定位，不拿类名/断言数量代替效果。失败给具体命令/关键错误/影响，问题给位置/触发/修正，人工事项给操作步骤，不用免责话术隐藏缺口。

复杂交付可用“问题是什么／采取了什么措施／目前成果是什么”三项；有并发状态变化时可附人员状态和业务进度两表，区分运行、结束、等待指派与实施/审查/回归/人工待验。简单任务一段足够，不强制模板和表格。阶段收尾或用户回顾再展开完整逻辑，返修只讲新改动和定向证据。

计划说明目标、验收、工作包、接口/所有权、人数理由和缺失决定；实施说明实际成果、自测、接口和候选；审查给等级/对象、PASS/FIX/BLOCKED、位置证据；集成给最终对象、相关回归和产物；人工报告只记用户反馈；提交发布写已授权范围、真实结果/链接或失败动作。

代码完成、独立审查、自动化回归、真实 ACP、用户验收分开。未运行、未送达、覆盖不足和待决项清楚标记。读者忽略前文也能理解，减少缩写、嵌套、原始日志和重复限定。真实失败、环境阻塞、旧预期冲突、新需求分别表述；无证据偏好不阻断。
