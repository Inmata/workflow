# 验证约定

## 验证

计划指定 Worker 本包自测、Lead 集成必要回归和用户人工验收，各有范围、执行环境和完成条件。审查复用有效证据；自测不替代组合验证，自动化不替代用户反馈。未执行或未进入目标路径不能写通过；全套失败和之后定向通过分别报告。

方便用户直接操作的文案、字体、图标、布局、光标、复制/选词、滚动、页面切换给简短步骤并标人工待验。仅用户明确要求时新增视觉自动化；不为这些需求建立截图矩阵、像素/坐标/字号断言、测试 seam 或 mock。背后的迟到响应、取消竞态、失败队列、解析 Unicode、删除边界和凭据隔离等难稳定观察逻辑按本次风险做最少必要自动检查。

优先项目已有命令/测试，确有关键缺口才补行为回归，不强制 TDD、新框架或自动化一切。断言对准产品失败，不添加公开几何查询接口来验证内部绘制。集中完成相关修改后执行指定验证，集成仅补组合风险；默认套件成本合理且无定向入口时可单轮全测。

原现象、期望、事实与假设分清；日志最后一步不单独证明根因。真实宿主必要时复用已证明入口，宿主未触发路径给覆盖不足及补查步骤。零布局不抛异常不能冒充有布局的原场景通过。已有非确定性失败才有限重复，先定次数和停止条件。

失败先读完整输出、实际程序/参数/目录/退出码/产物；单实例提前退出不是成功。按证据 → 原因 → 最小修正 → 定向复验。构建产物被占用不结束用户程序，使用现有脚本隔离输出，报告实际位置。缺接口继续独立部分，不重复依赖失败，不越界补实现。复验沿用已验证环境，避免临时建立多套链路；护栏/超时/重试变更需计时或失败证据及审查，不靠放宽护栏过关。

首轮完整保存命令输出，后续为看结果标签不重跑。新变更/实际失败/具体风险使证据失效时才补验证。复验仍失败交 Lead 判断产品缺陷、旧预期冲突、环境阻塞或原场景待验；产品修改按原负责人/必要复审处理。不删除测试或弱化断言制造通过。结果前不宣布可集成。

## 停止限制

| 限制 | 计数范围 | 到限 |
| --- | --- | --- |
| 指定验证首轮失败后的定向修复 | 每工作包默认一次修复和受影响复验 | 仍失败交 Lead 裁决 |
| FIX 连续返修 | 同包最多两轮 | Lead 缩范围、改方案或请求必要信息 |
| 诊断无新产品证据 | 连续两轮 | 收敛；换宿主/工具不算新产品证据 |
| workflow 经验查漏补偿 | 同任务额外一轮，持久化 | 留知识待办并放行交付 |

四项独立，不共用 retryCount，不因改包名/任务名、换人、升级审查、会话恢复或压缩重置。角色记录前三项，插件强制最后一项。已有授权与负责人、依赖满足后接续，否则只暂停相关工作。
