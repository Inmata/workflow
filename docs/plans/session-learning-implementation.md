## 2. 逐项结果

### F11 route 与通道仍是声明

**结果。** 协议和角色说明明确 `route` 只决定门禁与检查范围，不是任务复杂度认证；用户明确要求 Worker/Reviewer 后，Lead 不能用 `operation-only` 或 `lead-direct` 消除分工。用户指定通道后，工作包通道偏离必须在同一 `packages` 信号附 `change.packages`，否则返回 `CHANNEL`；不能先声明错误通道再以实际执行一致为由通过。没有新增自然语言任务分类器或全工具监视。

**公开场景。** `test/protocol-review.test.mjs` 的 F11 用例固定三种合法 route 的原有契约，并验证指定通道后的偏离：无 `change` 被拒，有 `change` 接受。

**边界。** `route` 与 `channel` 仍是声明和门禁契约，不认证实际任务复杂度、真实派工意图、只读事实或代码是否集成。

### F12 已审包可经 canceled 绕过审查

**结果。** 任务账本新增单调 `reviewPasses`，保存曾有 PASS 的 worker 包。曾有 PASS 的包（含沿 `supersedes` 链的历史事实）改 `canceled` 返回 `PACKAGE`，原记录不变；同一批把审查改成 `FIX`/`BLOCKED`、先改 `FIX` 再取消、或把审查对象改指其他包，都不能抹掉曾 PASS。同包返修再次交付后旧 `reviewedRef` 不再匹配新的 `deliveredRef`，必须重新审查；换新包只能在创建时声明 `supersedes`，接替包需要自己的 PASS。从未有 PASS 的包仍可合法取消，已合法 `waived` 的语义不变。

**公开场景。** `test/protocol-review.test.mjs` 的 F12 用例覆盖 PASS 后取消被拒、未审取消、同批改写与改指、旧账本缺失 `reviewPasses` 时动态推导、同包返修、`supersedes` 链和两种数组顺序。`test/signal.test.mjs` 的 F12/F14 用例覆盖同批重复 `packageId` 整批回滚。

**边界。** `canceled` 只表示放弃该包改动，不证明代码已从最终 ref 消失；门禁只核对声明记录，不提供代码级集成证明，Lead 仍对集成结果负责。

### F13 信号失败后不消费回执

**结果。** 用真实 PostToolUse 合成事件固定“生成信号 → 接受/拒绝回执 → 修正声明 → 重发”的闭环。拒绝以 `accepted:false` 和 `reason` 定位，覆盖 PASS 缺 `reviewedRef`、`reviews` 指向未登记或非 worker 包、状态/角色错误、审查版本不匹配等；修正后重发接受。同 `signalId` 同正文重试幂等，改正文返回 `SIGNAL_ID`；CLI 成功退出不等于 `accepted`；未落盘的失败信号不猜测内容、不自动重放。

**公开场景。** `test/signal.test.mjs` 的 F13 用例逐类断言拒绝原因、幂等重发和接受结果，并检查 Stop/task-end 与账本一致。

**边界。** 插件只保证拒绝原因可见和失败信号可安全幂等重发，不能保证模型一定阅读回执；“回执存在但未消费”仍是宿主/模型行为边界。

### F14 只读诊断与简单操作被过度拆包

**结果。** 只读诊断包只能在首次创建 worker 包时用 `diagnostic:{purpose, scope[], reason}` 声明免审：包必须为 `dispatched`，不能带 `deliveredRef` 或 `supersedes`，`scope` 为 1–50 项项目内相对路径，用途与理由非空。声明进入包记录和 `gateReport`；交付时必须在 `note` 写可定位结论与证据，否则列 `diagnostic:<id>` 且不能用 waiver 抵扣。实现包、审查包、事后补声明或修改声明、空理由、空/绝对/越界范围、接替已审包都返回 `PACKAGE`；历史未声明包保持原门禁。

**公开场景。** `test/protocol-review.test.mjs` 的 F14 用例覆盖合法声明、缺结论、各类拒绝和历史包；`test/signal.test.mjs` 覆盖批内先消费再补挂 `diagnostic` 的绕过路径。

**边界。** 声明只表示事先约定，插件不验证进程实际未写、不提供沙箱，也不检查结论真实性。

### F15 文档、注释与当前状态互相矛盾

**结果。** `src/hooks.mjs` 与 `src/spec.mjs` 的预算注释改为实际语义：4 秒是预检内 Git 调用共享的绝对截止预算，同步文件读取不可中断且同样消耗剩余时间，锁内 ref 复核另有独立预算，不承诺整个 Hook 在宿主 10 秒窗口内返回。开发入口与总计划区分当前安装状态和历史 0.7.0 记录，历史记录不逐条改写成新事实。

**公开场景。** `test/hooks.test.mjs` 与 `test/spec.test.mjs` 固定预算有界、过期不可复用和 lock 外预检行为；`npm run check` 检查语法、版本、发布清单和本地链接；本节和验收文档核对注释与公开表述。

**边界。** 4 秒仍不是预检或 Hook 的总时长上限；宿主真实终止和超大仓库耗时未实测。

### F16 任务结束后的候选经验提取

**结果。** 项目已启用学习、任务未声明 `permissions.learning=false` 且宿主提供 `transcript_path` 时，被接受的 `task-end` 登记一次幂等候选提取作业；同一 `task-end` 重放、Stop 和普通 Hook 不重复登记，业务任务不等待模型，提取失败不回滚或阻塞任务。输入只取 transcript 中用户与助手的短文本，工具调用、工具结果和超长输出在预算前剔除；只接受宿主给出的绝对路径普通文件，限制扩展名与大小。身份必须正面成立：Claude 每条被采用的 user/assistant 记录都要带当前 `sessionId`，Codex 必须有与当前会话一致的 `session_meta`；缺失或不一致整份按 `TRANSCRIPT_IDENTITY` 跳过。模型只返回候选观察，证据必须指向本次 transcript 中的用户消息；候选经既有材料校验和敏感信息检查后只写 `inbox`（`origin:auto-extract`），不直接创建或修订正式知识。引用已有 `knowledgeId` 的明确纠正或已验证失败与人工采集一样登记即时反例，并唤醒同知识或同条件的 `waiting` 材料。

**公开场景。** `test/capture.test.mjs` 的 F16 用例覆盖：task-end 登记与重放不新增、早期纠正形成带证据候选、零候选、助手总结和工具日志不能变成经验、禁用学习和无 transcript 时零模型调用、读取/格式/身份/超时/无效输出不阻塞、输入预算、绝对路径普通文件、目录链接与文件符号链接拒绝、自动反例与人工采集共用处理。

**边界。** 真实模型和真实长 transcript 未调用；测试只使用人工重写的最小脱敏样本；文件符号链接用例因当前 Windows 账户权限跳过；不承诺覆盖所有宿主 transcript 格式。

### F17 一项无效提案导致整批复盘失败

**结果。** 复盘改为按决定逐项校验。合法决定及其材料结果在同一事务提交；非法决定只产生决定级原因，材料保持 `pending` 并记录 `lastRejected`（运行 ID、代码、说明），可原样重试。存在拒绝时运行状态为 `partial`，返回拒绝数量与原因；全部决定无效时为 `failed`，不写知识；已有失败或终态运行不被改写。同一材料被多项决定引用、跨批引用、同一知识被多项决定修改时保守拒绝相关决定；模型完全未处置的材料不算拒绝，保留在 `pending` 并列入 `unhandled`。改变旧结论、降级、替代、偏好证据和范围校验的门槛没有放宽。

**公开场景。** `test/learning.test.mjs` 的 F17 用例覆盖四项决定部分成功、全部无效、多材料决定、跨批引用、同一材料和同一知识重复、写入冲突与恢复重放；`test/capture.test.mjs` 的 F18 用例同时核对 `partial` 运行在报告中的呈现。

**边界。** 没有重放真实模型 answer，也没有把真实运行记录作为 fixture；测试只使用人工重写的最小结构。

### F18 学习状态没有呈现吸收漏斗与召回效果

**结果。** `learning status` 成为只读漏斗报告，给出统计时点 `at` 和范围 `scope`，分开展示材料 `pending/waiting/processed`、证据类型、反馈 `shown/adopted`、最近运行状态与被拒原因、知识创建/修订/替代数、提取作业状态与用量，以及复盘和提取各自的当日额度。材料、反馈和提取作业可用 `--session`、`--task` 过滤；缺少会话归属的记录单列 `unattributed`；复盘运行和知识文件按项目统计并标注 `project`，不与过滤后的材料数混算。没有反馈记录时写“无记录”；`knowledge select` 只是查询，不计为 `adopted`。

**公开场景。** `test/capture.test.mjs` 的 F18 用例核对材料、运行、知识、反馈、提取作业的分项计数、`scope` 与 `unattributed`，以及会话过滤和项目累计额度。

**边界。** 报告口径不是效果证明；真实项目材料未被处理。脱敏合成归因示例可按“6 份材料、0 份正式知识”重放，只用于验证报告能否区分材料与知识，不表示真实材料已 `processed`。
