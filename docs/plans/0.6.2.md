# 0.6.2 计划：派工通道、返修链与审查豁免

来源：helper 仓库会话“群聊机器人拟人化与主动接话”（分支 fix/mention-reply-quality）的复盘。该会话暴露的问题按能否由插件机械核对分两类：能核对的本版做成规则或校验，不能核对的只改文档，留后续。

## 问题与取舍

| # | 现象（证据） | 本版处理 |
| --- | --- | --- |
| 1 | 用户指定“worker 是 claude code、reviewer 是 codex”，第 2、3 步 Lead 改用内置 Agent 子代理和自己实现，没说明（信号 `wf-s3-pkg1` handle=`lead-direct`） | task-start 可声明 `channels`，工作包带 `channel`；与声明不一致或 delegated 任务里 worker 包由 Lead 实施，必须在同一信号附 `change` 记录偏离，否则拒绝 |
| 2 | 内置子代理发了 role-claim，插件整体放行带 `agent_id` 的事件，信号无回执，子代理白忙 | 内置子代理调用本插件 signal 时回一条说明：它没有 workflow 身份，信号不记录，直接完成工作包交回 |
| 3 | 每轮返修换新 packageId（fix1/2/3、review→review4），两轮上限数不到 | 新增 `supersedes`：新包接替旧包时继承 attempts+1，旧包自动收尾；被接替的 worker 包不再要求单独审查 |
| 4 | 审查版本与交付版本不符，用 waiver 豁免通过；旧 worker 包标 waived 绕过审查（`wf-impl-end2`、`wf-s2-pkg14`） | 已有 reviewer 包审过的 worker 包，`review:<id>` 缺项不能豁免，只能让审查对上最终交付版本或用 supersedes 接替 |
| 5 | Stop 在途提示固定写 Codeg，内置子代理其实会通知父会话 | Stop 按在途包的 channel 分别给提示 |
| 6 | 等待中 62 次状态查询只有 3 次 check_user_feedback；Reviewer 包多数没带 role-claim 与 reviewer 指引；Lead 自己调试导致多次压缩 | 只改文档：Lead/Codeg 指引写清通道沿用、内置子代理的身份限制、返修用 supersedes |

分歧点的选择：

- 通道偏离用“拒绝，除非附 change”，不用“只警告”。会话里的警告和规则都被忽略过；附 change 不挡合理偏离，但留下记录、迫使说明。
- 不禁止内置子代理：有的场景用户就是要它。插件只说明它没有身份，并让通道声明暴露偏离。
- 豁免限制只针对“已经审过”的包。从没安排审查的包仍可按原规则豁免，避免把 Lead 判定无需审查的小包也锁死。
- `supersedes` 是可选字段；沿用同一 packageId 重新派发的旧做法不变。

## 不做（留后续）

- signal 自动填身份字段、快照辅助命令：需要 CLI 读当前会话身份或执行 git 写操作，范围大，单独设计。
- 统计 check_user_feedback 次数：插件看不到 Codeg 反馈工具的语义结果，计数容易误报。

## 防止越改越乱

- 新规则都落在 `upsertPackages` 和 `gateReport` 两处，各抽一个小函数；不新增 action、phase 或状态文件 schema。
- 新字段全部可选；不用它们的任务与 0.6.1 行为相同，现有测试不改断言。
- 每条规则配一个正向、一个拒绝用例。

## 条目

1. 协议：`channels`、`channel`、`supersedes`、豁免限制、Stop 分通道提示、内置子代理信号说明。
2. 测试：gate、hooks 相关用例。
3. 文档：protocol、lead、workflow、usage、codeg/claude 适配、README 中英文。
4. 版本号 0.6.2。

## spec 影响

无（本仓库没有 `.spec`）。

## 进度（已完成）

条目 1-4 全部完成。新用例在 `test/channels.test.mjs`（8 个），全量 `npm test` 136 个通过，`npm run check` 无错误。

自审发现并已修复：

- 高：沿 supersedes 换新包号可绕开“已审包不可豁免”。改为沿接替链回溯，链上任一包有审查结论即算已审（`wasReviewed`）。
- 中：被取消、失败而没给结论的 reviewer 包也把 worker 锁死。改为只认有 `verdict` 的审查包。
- 中：被接替的旧包还能改状态重新打开。现在返回 `PACKAGE`。

按设计保留：canceled 仍是显式放弃已审包的出口（放弃即不交付该改动）；同一信号内的包按顺序处理，先写审查结论再改 waived 会被拒。

越改越乱的评估：新增逻辑集中在 `upsertPackages`、`gateReport` 和一个 `wasReviewed` 辅助函数，豁免与 waived 两条路径共用同一判定；没有新 action、phase 或状态 schema。门禁 PASS 核对仍独立，没有交叉。风险可控。

遗留（低，留后续）：通道偏离按字符串精确比较，不做别名归一；`compactLedger` 摘要不含 `channel`、`supersededBy`，需要时用 `task show` 查看。
