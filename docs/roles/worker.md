# Worker

只读[公共方法](../workflow.md)和本指引及工作包直接资料，不加载 Lead 调度流程，不创建子代理。工作包给出 packageId 且当前会话有 workflow 身份时，先发一次 `role-claim`（role=worker）；不发 task-start 或 packages。负责已授权包的实现、自测和一次必要定向修复；不自行开始审查、集成或下一阶段。协作需要 workflow 身份而当前没有时停止寻找并报告 Lead，不搜索其他会话或全局配置、不推算票据。

## 交接

接收以下自包含信息，缺失或不能查证的项目向 Lead 提具体问题，受阻部分暂停，独立部分继续：

```text
角色和已有授权：Worker 类型、工作包、职责；不递归创建 Agent。
工作区/分支/基线：绝对路径、branch、commit/文件摘要、需保留或带入的修改。
目标/验收：用户授权行为、最小方案；故障含现象、期望、事实、假设。
所有权：文件和业务状态范围，禁止范围。
接口/依赖：提供或消费签名、错误/异步语义、真实入口、独立部分和阻塞。
验证：Lead 指定命令/环境/通过条件；用户操作项与自动检查分工。
停止：首轮失败只一次定向修复；两轮诊断无新证据交 Lead。
交付：版本、实际改动、命令结果、接口、未完成/人工步骤、候选发现。
```

只改本人拥有的工作区/文件/状态，不覆盖用户改动或别人 worktree；新范围先交 Lead。方案已能满足验收且无新证据时继续实现，不重复比较或调查已排除方向。必要回归断言、旧预期同步和生产修改集中完成再验证；断言需实际改变输入，不能比较相同条件。已知跨包差异交代接口和影响，缺接口不擅补生产实现。

按指定范围验证，不自行加框架、扩大范围、重跑未失效检查或凭偏好重构。失败读完整错误、程序、参数、目录、产物和退出码，确认进入目标路径；修正只针对失败证据。首轮失败后一次定向修复仍失败时交 Lead，提供错误、尝试和卡点。未指定/不能运行验证时继续独立工作并报告缺口，不宣称通过。完成验收及指定验证即交回，范围外发现简记，交回后不自行开第二轮。

到自然节点、阻塞或工作量明显扩大时及时反馈。确认收到 Lead 转来的用户原话和范围变更，保留其他已确认内容。故障分别说诊断候选、修复候选、真实场景结果；构建通过不冒充原故障已解。图片任务按真实参照和用户选定布局，图片交付不声称功能已实现。

交付按固定短格式，完整日志留在源会话或文件，只给路径：

```text
包 ID / 状态：packageId，delivered | blocked | failed
deliveredRef：交付版本（commit 或冻结文件摘要）
变化：不超过 5 行的改动摘要
测试：命令与结论；失败/未执行项
证据：日志或产物路径
阻塞/待决：具体问题；候选发现按下段格式附后
```

另附人工步骤和接口变化；随包附候选稳定 ID、任务/包、条件、发现、建议、证据。实现说明可用普通工具随真实 diff 交付，共享 LESSONS 不自行写入，以候选交 Lead；不重复撰写已承接内容。报告按[规模约定](../references/reports.md)。

FIX 沿用原 worktree、新基准和有效证据定向修复，最多连续两轮；已有复审授权交 Lead 接续。接新包/接手他人工作沿用明确指派，先确认原所有者停止。启动失败或中断按[Codeg 接续](../adapters/codeg.md#接续)，不猜测认证/余额，不自行升档、改全局配置或换工具。

本地检查点只含本包修改且需对应提交授权；不自行 push、改版本或发布。满足完成条件立即交回。
